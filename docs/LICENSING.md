### Compatibility with the old names (`dev.cadence.metal.Legacy`)

* **System properties.** `Legacy.migrateProperties()` copies every `mcopt.X` to `cadence.X`, `minecraftShaders.X` to
  `cadence.shaders.X`, `minecraftScene.X` to `cadence.scene.X` when the new key is not set (a new key always wins). It
  runs first in `Profile.apply()` (which every metal mixin plugin and the preLaunch entrypoint call before reading any
  flag), again in `JvmDefaults`, and in the shaders module's `CadencePackGate` (static init) and `CadenceMixinPlugin`. The
  rest of the code reads only the new names, so no read site (about 560) needed a fallback of its own. Because a Java
  re-exec (JvmDefaults) repeats the original command line, old `-D` flags survive it too.
* **Config files.** `Legacy.readable(dir, new, old)` returns the new file if it exists, else the old one if it exists,
  else the new one. Readers use it (`Profile`, `JvmDefaults`, `CadencePackGate`, `ShaderLoaderConfig`,
  `ShaderToggle.load`). Writers (`ShaderToggle.saveKey` and the first-launch default of `Profile`) always write the new
  name, so the first save copies the old settings across (the save loads the old content first and keeps its other
  keys). The old files are never modified or deleted. `Profile` also accepts old `mcopt.*` keys inside either file and
  reads them as `cadence.*`; a `cadence.*` key in the file wins over the old one.
* Checked by running `Legacy` on its own (old and new keys, both orders, files present/absent); the game was not run.

### Credit and license

* **License for Cadence's own code: Apache-2.0** (the existing `LICENSE`). Reason: mcopt, the larger and Apache-2.0
  licensed half, requires derivatives to stay Apache-2.0 compatible, and MIT code can be combined into an Apache-2.0 work
  as long as its notice is kept. No other license was introduced. The copyright line for new code is "the Cadence authors"
  (placeholder: the real name(s) can replace it in `NOTICE`, `CREDITS.md` and the fabric.mod.json `authors`).
* `NOTICE` rewritten: Cadence header, the mcopt NOTICE reproduced verbatim (Apache-2.0 4(d)), a statement of changes
  (4(b)), the MIT paragraph (what came from the Shader Loader, commit `c609745`), and what is not included.
* `CREDITS.md` added: what Cadence is, a table of parts / upstreams / authors / licenses / commits, third-party check,
  the old-name compatibility note, credit for ByteV0rtex's idea (kept from an existing comment).
* Per-file notices (single consistent line, as the first line of the file):
  * `// Cadence: derived from mcopt (c) Noah Dunnagan, Apache-2.0; modified.` on the 240 Java / native / Metal files of
    `metal/` and `fpshud/` that exist in mcopt commit `7b1d0fb` (found with `git ls-tree`).
  * `// Cadence: derived from Minecraft Shader Loader (c) Minecraft Metal Renderer contributors, MIT; modified.` on the
    124 files of `shaders/` that came with the import commit `d1aca00`, except those under `shaders/cadence/` and classes
    named `Cadence*`, which are Cadence's. (MIT asks for no file notices; this is for clarity.)
  * `MetalPassHints`, `MetalPipelineMath`, `SpirvMathPolicy` keep their existing "Adapted from minecraft-metal-renderer"
    header and get no second line.
  * Files added by Cadence after `7b1d0fb` carry no derived-from line.
* The MIT text (`shaders/LICENSE-MIT-shader-loader`, "Copyright (c) 2026 Minecraft Metal Renderer contributors") is kept
  and is now also packed into the metal jar (it already was in the shaders jar), because three metal classes are MIT
  adaptations. `LICENSE` and `NOTICE` are in all three jars as before.
* Third-party check: no shader pack, font, image, sound or other asset is tracked; no library is shaded into a jar; the
  native library links only Apple frameworks. BSL appears only as a pack name in docs, test scripts and comments.
* Existing attribution comments were kept (ByteV0rtex / `noahdunnagan/mcopt#2`, "Adapted from minecraft-metal-renderer").
* `fabric.mod.json`: authors "Cadence authors"; `contributors` list "Noah Dunnagan (mcopt)" and "Kausik Velaga (Minecraft
  Shader Loader)"; `license` Apache-2.0 (shaders: Apache-2.0 and MIT); `custom."cadence:upstream"` lists the upstreams.

## 3. Intentional leftovers of the old names

* License and credit text: `LICENSE`, `NOTICE`, `CREDITS.md`, `shaders/LICENSE-MIT-shader-loader`, the "Cadence: derived
  from mcopt / Minecraft Shader Loader" file lines, the "Adapted from minecraft-metal-renderer" headers,
  `fabric.mod.json` contributors/custom/sources, README/RELEASE-README origin text, the `noahdunnagan/mcopt#2` idea credit.
* Compatibility code: `Legacy.java` (old prefixes and file names) and the legacy-key handling in `Profile.java`;
  `.gitignore` keeps `mcopt-pack-cache/`.
* `mcopt.bench.Bench`: a class name looked up by reflection in `FrameCapture`, `Cpu`, `AbShots`, `Recorder`. It is
  mcopt's separate bench harness and is not in this repository; the lookup is optional, so the string is left alone.
* Native: C symbols `mc_*`, `libmcmetal.dylib`, file names such as `mcmetal.m` (the "mc" is Minecraft, not mcopt).
* Java class names that still say "ShaderLoader" (`ShaderLoaderMod`, `ShaderLoaderConfig`) and the inner
  `dev.cadence.shaders.cadence` package: left as they are (renaming classes would be a refactor, not a rename of names).
* History documents keep their old names, with the old -> new table at the top of `CHANGES-FROM-MCOPT.md`: `dev-log/PLAN.md`,
  `CHANGES-FROM-MCOPT.md`, `dev-log/DAY2.md`, `dev-log/OVERNIGHT.md`, `RESEARCH-*.md`, `dev-log/DESIGN-DAY3.md`.
* `shaders/UPSTREAM_COMMIT` (c609745) unchanged.
* Untracked `metal/run/` (gitignored dev run folder) was not touched: it still holds `config/mcopt.properties`,
  `config/minecraft-shader-loader.properties` (both still read through the fallback), an old `mods/cadence-fpshud.jar`
  (mod id `mcopt-fps`, still loads by itself) and `mods/cadence-shaders.jar` (replaced by `tools/cadence-test.sh` from the
  new `shaders/build/libs/cadence-shaders-*.jar` when that is newer; the old one would fail on its `mcopt-metal` dependency).
