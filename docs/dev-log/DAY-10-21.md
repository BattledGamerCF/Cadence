# 2026-10-21 (day): Vivace 27, and Cadence running on it

The user's asks, in order: optimize the raw Java build (Vivace), test it rigorously, then a deep legal pass on how the
mod can run on that Java given OpenJDK's GPLv2. The Java build lives in `../jdk-project` (its PATCHES.md, PLAN.md and
research/LEGAL2.md hold the detail); this log covers what touched Cadence.

## Optimizing the build: rebase on JDK 27
- Flag-level tuning of Vivace 25 was exhausted (UseSIMDForMemoryOps, isb spin-wait: no difference in ABBA CPU runs).
- Built JDK 26 (to bootstrap) and JDK 27.0.1. Minecraft 26.3 + Fabric + Cadence run on 27 unchanged.
- Plain 27 vs Vivace 25, crowded scene: the same fps, render CPU and tick time.
- Vivace 27 (the same three patches, ported) vs Vivace 25, 4-minute flights with menus, ABBA: smaller heap, fewer long
  young pauses. **It didn't last**: in 14-34-minute flights JDK 26+'s heap sizing (it counts concurrent marking as GC
  overhead, and Cadence starts marking every ~25 s) grew the heap toward -Xmx and filled it with eden: 193 young pauses
  over 8 ms vs 41-51 on 25, ~200 MB more resident. Tried: GCTimeRatio=12, MaxGCPauseMillis=10, a Vivace patch counting
  pause time only: none enough alone. **Young generation capped at 128 MB** (Cadence default on Java 26+): 27 = 25
  (58 over 8 ms, same resident memory). Vivace 25 stays recommended (LTS).

## Cadence changes (beta.12)
- **Video Settings > Java: Launcher's / Vivace** (`dev.cadence.metal.Vivace`, `JvmDefaults`). Opt-in. At the start of
  loading, the restart Cadence already does for its Java defaults goes to Vivace's `java`, after a `-version` probe with
  the player's -XX options. Fallbacks: refused option, quarantine block, missing Vivace, or a start that never reached the
  game (config/cadence-java.properties keeps a pending/failed note). Found in ~/Library/Application Support/Vivace
  (doesn't change Terminal's default java) or the system Java folders; `cadence.java=PATH` for a specific one.
- Java 27 deprecates -XX:InitiatingHeapOccupancyPercent (warning at every start): Cadence passes -XX:G1IHOP on 27+,
  including when it restarts a Java 25 launch onto Vivace 27.
- Java 26+: -XX:MaxNewSize=128m in the Java defaults (G1 only, the player's young sizing wins), also when restarting a
  Java 25 launch onto Vivace 27.
- tools/logic-tests/VivaceCheck.java: 15 offline checks (which Vivace is chosen, settings precedence, probe refusal,
  pending/failed notes).

## Testing
- jtreg on Vivace 27: 171 passed, 0 failed.
- Dev: a Zulu 25 launch with -Dcadence.java= restarted onto Vivace 27 (G1IHOP, no warnings); the Java button shows in
  Extras.
- Production (metal/run-compat, 18 mods): on Vivace 27 directly (beta.11 jar), and with beta.12 launched on Zulu 25 with
  java=vivace in the config, restarting itself onto the Vivace in Application Support. Same log errors as on 25
  (offline-account sign-in, AppleSkin's Mod Menu hook). One benchmark was stopped by Essential's offline-account popup
  ("Stopped: a screen opened."); a re-run completed.

## Legal (summary; ../jdk-project/research/LEGAL2.md)
Vivace is a separate program and download; Cadence never ships, downloads or links any of it, and talks to it only
through exec, the release file and public MXBeans. Running on a JVM puts no GPL duty on the mod. Release-side GPL fixes
made today: build scripts now in the source archive, bug URLs no longer point at Oracle, runtime release file names the
implementor, trademark legend added. Left for the user: notarization, a trademark search for "Vivace", reading the
Minecraft EULA, asking CurseForge moderators about the text mention, a public Vivace repository.
